# Contracts

Reference implementation of the disclosure registry and the vault described in
`Agama x Horizen - Technical Architecture.pdf`. It exists so the architecture
can be checked rather than believed. It is not a product: the book behind every
figure is synthetic, generated by [`../zk/gen.py`](../zk/gen.py), and nothing
here has been audited.

## What is in `src/`

| | |
| --- | --- |
| `CreditDisclosureRegistry.sol` | Holds the book commitments, the forward cash calendar, the collections observed on-chain, and the attestation log. A surface is only admitted if a proof verifies against the committed root, the valuation date is not in the future, no leaf predates the commitment, and the claimed principal never exceeds what the chain watched leave the vault |
| `AgamaCreditVault.sol` | ERC-4626. NAV is computed from the proven surface and a fixed impairment schedule rather than asserted. First-loss capital is escrowed and its depletion is public. Exits go through a public queue settled strictly pro-rata at one ratio, and `settle()` is permissionless |
| `IRiskSurface.sol` | MIT, no dependency on anything else here. `surface()`, `impairedPrincipal()`, `scheduledFor()`, `realizedFor()`, `performanceRatio()`, `attestationAge()`, `concentration()`. This is the part another Horizen protocol reads to underwrite the vault without asking us anything |
| `ZkVerifyRiskSurface.sol` | The zkVerify route. Recomputes zkVerify's statement on-chain from the seventeen public inputs and the verification key, then admits the surface against an aggregation root |
| `AggregationStandIn.sol` | Holds the real zkVerify aggregation root on Base Sepolia. Exists because no domain relays a root to an EVM chain by configuration. See [`../zk/zkverify/`](../zk/zkverify/) |
| `HonkVerifier.sol`, `DeltaVerifier.sol` | Generated by Barretenberg from the two Noir circuits. Do not edit: `../zk/prove.sh` regenerates both, byte for byte identical to what is deployed and source-verified on Horizen |
| `TestUSDC.sol` | Six-decimal ERC-20 for testnet only. Horizen mainnet has real USDC.e at `0xDF7108f8B10F9b9eC1aba01CCa057268cbf86B6c` |

## Tests

```sh
forge test
```

Forty-seven tests, all passing.

| Suite | Count | What it does |
| --- | --- | --- |
| `HorizenFork.t.sol` | 7 | Runs the whole disclosure cycle against a fork of Horizen mainnet pinned at block 26,170,000, so the gas figures in the paper are real numbers on the real chain |
| `Adversarial.t.sol` | 23 | Attacks the design rather than demonstrating it. Backdated leaves, replayed and mis-parented revisions, stale surfaces, principal without disbursement, queue jumping, role escalation |
| `Invariant.t.sol` | 6 | Stateful invariants over 4,096 randomised calls |
| `ZkVerify.t.sol` | 11 | The aggregation route, against the real root published on Volta |

The fork is pinned, so the first run fetches state once and every later run
reads it from the local cache. Override the endpoint with `HORIZEN_RPC` if the
public one is slow.

**This suite found six defects in these contracts**, one of them serious: a
sweep function let the admin key send every collected borrower payment to an
address of its choosing while the comment said it went to the vault. All six
are fixed, tested and redeployed. The tests are written to break the
architecture document's claims, which is the only way they are worth anything.
